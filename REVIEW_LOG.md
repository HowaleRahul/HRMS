# Production Readiness Review Log

Review date: 2026-09-29
Scope: repository-wide review in progress; findings below are verified only to the extent stated.

## Confirmed Findings

### Functional correctness
- [x] **Password reset emails contain literal interpolation expressions** (`server/controllers/auth.controller.js`, High). The reset URL and email body escaped `${...}` inside template literals, so recipients received a nonfunctional URL. Reproduce by requesting a reset for a known account and inspecting the generated message. Fixed by restoring normal template interpolation; source-level assertions passed.
- [x] **Password reset persistence uses nonexistent columns** (`server/models/auth.model.js`, Critical). Reset-token reads/writes referenced `reset_token` and `reset_token_expires`, while the schema defines `password_reset_token` and `password_reset_expires`; a valid reset request therefore fails against this schema. Fixed the model/controller column contract; source/schema assertions passed, but no DB-backed test ran.
- [x] **Database setup destroys the entire database on every run** (`server/database/schema.sql`, Critical). The setup script executes this schema, whose first DDL dropped `hrms_db` before recreating it. Re-running documented setup permanently erased all accounts and HR data. Removed the `DROP DATABASE` statement; schema initialization is still not migration-safe/idempotent and must not be used for upgrades.
- [x] **Seeded admin credential did not match documentation and was a known static password** (`server/database/schema.sql`, High). The SQL hash matched `password`, not README's `Admin@123`. Removed the hard-coded user/hash; setup now requires a unique `ADMIN_PASSWORD` of at least 12 characters and hashes it before seeding the initial admin. Bootstrap source assertions passed; setup was not run against MySQL.
- [x] **List screens treated API envelopes as arrays** (`client/src/pages/{documents,holidays,notices,settings}/*.jsx`, High). Backend responses wrap results in `data`, while these pages passed the full `{ success, data, ... }` object to `.map()`, causing blank/erroring views. Updated affected screens to unwrap `response.data.data`, and corrected Documents row labels to match API fields. Scoped lint and final production build passed.
- [x] **Unused Quill dependency carried known XSS advisories** (`client/package.json`, Moderate). `react-quill`/Quill 1.3.7 had two npm audit advisories and no application imports. Removed the unused dependency; frontend dependency audit now reports zero vulnerabilities.
- [x] **Password reset had no usable frontend and leaked reset tokens to logs** (`client/src/pages/auth`, `server/controllers/auth.controller.js`, High). Login linked to `#`, no reset pages/routes existed, and SMTP failure logged the full reset URL/token. Added forgot/reset pages and routes, raised reset/change/new-user password minimum to 12, and removed token logging. Frontend production build passed; SMTP flow untested.
- [x] **HR document files were publicly served and metadata exposed disk paths** (`server/server.js`, `server/controllers/document.controller.js`, High). Every upload was under an unauthenticated `/uploads` static mount; direct document reads also lacked a permission check. Removed public static serving, hide storage paths, added permission-gated metadata/file reads and an authenticated download flow, constrained upload fields, and clean up rejected files. Existing files are no longer publicly served. Browser download and DB-backed access tests pending.
- [x] **All primary HR modules were eagerly bundled into the initial route chunk** (`client/src/App.jsx`, Moderate). The production entry was 659 KB minified (198 KB gzip), triggering Vite's >500 KB warning. Converted route modules to lazy imports behind a shared Suspense fallback; entry is now 353 KB minified (115 KB gzip), no oversized-chunk warning.
- [x] **Known fallback JWT signing secrets enabled token forgery** (`server/config/config.js`, Critical). Missing production env variables silently selected public literal secrets. Removed those values, use random process-local secrets in non-production, and fail production startup for weak/missing/reused secrets, root/empty-password DB access, or a non-HTTPS client origin. Local configured key length/distinctness and config import passed; production-mode deployment test pending.
- [x] **Employee writes interpolated caller-controlled SQL column names** (`server/models/employee.model.js`, High). `create`/`update` built SQL identifiers directly from `req.body`, allowing unapproved column mutation and identifier injection attempts. Restricted both operations to explicit employee field allowlists and reject empty updates. Focused assertions passed. Other models still contain dynamic-column builders and need individual field allowlists.
- [x] **Payroll insert/status/payslip fields disagreed with the schema** (`server/models/payroll.model.js`, Critical). Generation inserted nonexistent `allowances`/`deductions` columns, while the schema requires detailed salary/tax amounts; status enums and transaction-reference column names also differed, designation used nonexistent `name`, and payslip arithmetic read nonexistent tax fields. Mapped inserts/statuses/joins/calculations to actual schema, calculate totals server-side, cap bulk batches at 500, and align the PDF currency label. Syntax/schema assertions passed; no MySQL instance was available.
- [x] **Leave requests trusted caller-supplied day counts and had non-atomic balance/overlap checks** (`server/controllers/leave.controller.js`, Critical). Strict string-vs-number ID comparison skipped the balance check; absent balances were accepted, client `total_days` was trusted, and simultaneous overlapping submissions could both pass. Server-calculated calendar days, required balances, overlap detection, pending-balance reservation, and employee-row locking now run in one transaction. Syntax/static assertions passed; approval/rejection/cancellation balance updates remain non-atomic and untested against MySQL.
- [x] **Authenticated APIs retained stale role claims and several record-level IDORs** (`server/middleware/auth.js`, High). Role/employee IDs were trusted from JWT for controller bypasses; notifications could be deleted by ID across users; attendance details and asset assignments lacked ownership scope; dashboard returned organization-wide payroll/activity stats to any signed-in user. Reloaded role/employee identity from DB, fixed `authorize`, added ownership checks, scoped notification deletes, restricted asset assignment reads, and required report-view permission for dashboard. Syntax/static assertions passed; permission behavior needs live DB testing.
- [x] **Employee report referenced a nonexistent designation column** (`server/models/report.model.js`, High). The query selected `designations.name`, but the schema stores `designations.title`, causing every employee report request to fail. Corrected the join projection. Source/schema assertion passed; DB-backed report validation pending.
- [x] **User creation/search/password editing were broken** (`server/models/user.model.js`, High). Creation inserted into nonexistent `users.password` instead of `password_hash`; search escaped interpolation and searched the literal `${search}`; edit UI accepted a password but the model ignored it. Fixed schema column, actual search interpolation, optional 12-character-hash password updates, and update-route validation. Model/schema assertions passed.

## Remaining Confirmed Risks

- **Default roles are not provisioned with permissions (High).** The schema contains a single role-permission seed for `super_admin`; roles `hr_admin`, `hr_executive`, `manager`, and `employee` have no permissions by default. After bootstrap, protected module APIs return 403 for them unless an operator manually configures the matrix. Reproduce by seeding and logging in as any non-super-admin; fix by defining/documenting a least-privilege matrix, including row-level scopes before granting self-service view permissions.
- **Logout and password changes do not revoke refresh/access sessions (Critical).** The client discards the refresh token; the server's access-token blacklist is process-local, logout does not invalidate refresh tokens, and password reset/change leaves already-issued JWTs valid. Reproduce by logging in, logging out, then POSTing the old refresh token to `/api/auth/refresh-token`; it can still mint an access token. Use persistent token/session versioning and revoke all sessions on logout/password changes.
- **Module permissions are not row-level authorization (Critical).** `employees.view`, `payroll.view`, and `documents.view` authorize broad list/detail data; several employee-facing routes return salary, bank details, and documents without checking that the record belongs to `req.user.employee_id`. Reproduce with a low-privilege account granted one of these module permissions and request another record ID. Add explicit self/team/HR scope policies in controllers and queries.
- **Leave approval, rejection, and cancellation are not atomic (High).** Request state and leave-balance mutations happen in separate operations; concurrent approvals or DB failure between writes can produce approved leave without a debit, or inconsistent refunds. Move each transition and balance update into a transaction with row locks and conditional status updates.
- **Dynamic SQL column construction remains in multiple models (High).** Asset, attendance/settings, department, designation, document, performance, and recruitment model methods still interpolate request-derived column names; apply explicit per-operation field allowlists and test malicious JSON keys.
- **Rate limiting and pagination permit resource exhaustion (High).** Global API limit is 5,000 requests/IP/15 minutes, reset-email requests have no route-specific throttle, limit values are not consistently capped, and several reports load unbounded result sets into memory. Add distributed rate limiting, reset-specific quotas, maximum page sizes, and export streaming/async jobs.
- **Payroll UI still reports mock success and undercounts lists (High).** `PayrollList.handleGenerate` only toasts success and does not call the API; its default API response is paginated to 10 while summary totals only those returned rows and there are no pagination controls. Implement generation workflow and pagination/server-side summaries.
- **Schema/bootstrap is not migration-safe (High).** `schema.sql` hardcodes `USE hrms_db` while runtime supports `DB_NAME`; table creation/seeding is not idempotent and there is no versioned migration system. A custom DB_NAME creates a split database; reruns now fail rather than erase data. Replace bootstrap with versioned migrations and validate config parity.
- **Startup/readiness is not production-safe (High).** DB connection failures are logged but the API still listens, route import failures are swallowed, and there is no health/readiness endpoint or graceful shutdown. Fail startup/readiness when dependencies/routes are unavailable.
- **Frontend accessibility and browser UX remain partially unverified (Medium).** Many icon-only controls elsewhere still lack accessible names; several labels are not programmatically associated with inputs; responsive/browser/keyboard workflows were not exercised. Run axe/keyboard/device testing and fix remaining controls.
- **Lint warnings remain across the client (Low/Medium).** Full oxlint exits successfully but reports numerous unused imports/catches and hook dependency/initialization warnings; validate effect behavior and clean warnings separately.
- [x] **Document upload allowed metadata mass assignment** (`server/controllers/document.controller.js`, High). The upload handler spread arbitrary multipart fields into a dynamic SQL insert, allowing a `documents.create` user to set verification/deletion columns. Replaced this with an explicit schema-backed field object and added title, document-number, and expiry-date validation. Focused checks pending.
